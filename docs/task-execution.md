# 任务执行与进度协议

当前实现覆盖模拟任务的提交、去重、持续消费、租约续期、取消和事件续传。已增加 Chat Completions 模式的多轮工具调用与用量事件；真实路由、外部业务副作用及企业登录仍待联调或接入。

## 提交与重试

`POST /api/v1/runs` 保留 `{"prompt":"生成报告"}`，也支持添加 `thread_id` 在已有会话中提交；同一会话只允许一个未结束任务，其他新请求返回 409。客户端可以额外发送 `Idempotency-Key` 请求头；取值为 1–128 个英文字母、数字或 `._:-` 字符。

- 同一租户、空间、用户下，相同键与相同 prompt、thread_id 返回同一个 `run_id`，不再创建任务或入队事件。
- 返回体反映任务的当前状态；首次提交和匹配的重试均返回 HTTP 201。
- 同一键被用于不同任务内容时返回 HTTP 409。
- 不同租户、空间或用户可以独立使用相同键，不会访问彼此的任务。
- 未提供键时，每次提交都是新任务。需要“重新执行”时使用新键。

去重由数据库唯一索引保证，覆盖并发请求。键目前随任务记录保留，不自动过期；此机制只解决提交去重，不代表外部业务操作已经实现幂等执行。

## 实时事件与断线续传

分页查询保持可用：`GET /api/v1/runs/{run_id}/events?after=0&limit=100`。

新增实时接口：`GET /api/v1/runs/{run_id}/events/stream?after=0`，返回 `text/event-stream`。每条持久化事件具有运行内递增的编号：

```text
id: 2
event: running
data: {"sequence":2,"event_type":"running","data":{"attempt":1},"created_at":"2026-10-28T00:00:00Z"}

```

客户端保存最近处理的 `id`，断线后通过 `Last-Event-ID` 请求头或 `after` 参数恢复；两者同时提供时，以请求头为准。事件仍需按编号去重，处理到成功、失败或取消事件后停止主动重连。任务结束且没有剩余事件时，重新请求返回 HTTP 204。

服务端约每 250 毫秒查询一次持久化事件，空闲时每 15 秒发送不含 `id` 的注释心跳。等待期间不持有数据库连接；客户端断开后停止该流的轮询。已有可选的模型正文流式推送，事件描述任务、工具执行进度及每轮模型用量；context_trimmed 记录上下文预算裁剪的计数，保持相同租约、权限和续传规则。`model_completed` 的数据字段、失败码与配置见 [大模型路由](model-routing.md)。

事件流需要与其他任务接口相同的 Bearer 认证。浏览器原生 `EventSource` 无法直接设置此认证头，前端应使用支持请求头的流式 `fetch` 或相应客户端，不能把令牌放在 URL 中。协议依据见 [HTML SSE 标准](https://html.spec.whatwg.org/multipage/server-sent-events.html)。

连接建立前，未授权任务返回 404。连接建立后，每轮查询及逐条发送前复查凭据和资源权限；令牌过期、撤销或资源不再可读时，以 `access_unavailable` 的 `stream_error` 关闭。存储不可用时，流返回不含游标的 `stream_error` 事件并关闭；客户端按已保存游标恢复，不跳过尚未收到的事件。

## Worker 运行模式

保留单次执行：

```bash
uv run --env-file .env --locked agentforge-worker --once
```

需要持续处理任务时，手动使用：

```bash
uv run --env-file .env --locked agentforge-worker --watch
```

`--watch` 按默认 1 秒间隔检查空队列；有任务时连续领取。收到 SIGINT 或 SIGTERM 后停止继续领取，并等待当前同步任务结束；空闲等待可以立即唤醒。它仍是单进程串行执行，一个 Worker 同时处理一个任务。

默认租约为 60 秒，后台心跳每 20 秒续期。可用 `--lease-seconds`、`--heartbeat-interval` 和 `--poll-interval` 调整；心跳间隔必须小于租约时长。

只有仍持有有效执行标识且执行授权有效的 Worker 才能续租、开始工具或提交结果。`database` 模式复查成员可写角色、共享 Agent 和 Hub Skill；撤权时当前有效尝试以 `access_revoked` 结束，放弃未完成工具记录，不接受迟到结果。撤销访问令牌仅停止对应访问，不等于取消已接受任务。详见 [身份与权限](identity.md)。任务取消、过期或被重新领取后，旧执行不能恢复租约或覆盖结果。续租失败后，当前尝试停止产生新的工具操作和最终结果写入，等待租约过期后由其他执行尝试恢复。

取消与租约失效不会强制杀死正在运行的同步 Python 函数；Chat Completions 请求已有网络超时和轮间执行检查，但在途请求不会即时取消。当前恢复允许重做纯内置工具；模型请求可能重发并重复计费，沙箱及外部业务操作仍需独立的中断与副作用核对机制。

## 工具执行事件

工具现在记录 `tool_started`、`tool_completed` 和 `tool_failed`。事件序号仍单调递增，客户端不应假定固定的最终序号。参数、结果、状态查询及恢复边界见 [版本化工具](tools.md)。

## 流式输出与执行尝试

模型文本分片是运行事件 model_text，包含 attempt、step、text、reset。每次写入仍通过当前执行标识、租约与权限检查，并在同一事务中生成 RPC 会话进度事件。该事件不是任务成功凭据；必须等完整响应通过校验后才执行工具或完成任务。重试隔离旧草稿，清空会话后旧 Worker 不能重新写回。运行审计保留部分文本，正式聊天与下一轮上下文仅使用成功结果。本轮不增加数据库表。

## 上下文裁剪事件

`context_trimmed` 在即将使用裁剪后的上下文请求模型前写入，包含 attempt、step、budget_chars、before_chars、after_chars、dropped_turns、retained_turns，不含被裁剪正文。`dropped_turns` 是本次请求新移除的历史轮数；`retained_turns` 是剩余历史轮数，不包括当前任务。事件写入失败或检查到取消、失效、撤权时不再请求模型。写入成功与外部请求不是原子操作，因此该事件不证明模型请求已经发生。

该事件仅进入 Run 审计与 REST SSE，不扩展原版 Rakazo 会话事件协议，不添加页面提示。Run / 消息保存完整内容；裁剪不是删除数据、摘要、长期记忆或计费记录。Worker 重试重新使用原有快照和历史，按当次模型回复决定后续请求是否需要进一步裁剪。

## MCP 读取与恢复

MCP 使用已有 tool_started / tool_completed / tool_failed 事件和工具调用记录，声明为 read。只接入由管理员审定、服务声明只读和幂等的查询工具。执行期间每约 100ms 检查取消 / 租约 / 成员权限，失效时停止本地等待并关闭连接；不能保证远端查询已停止或未计费。SDK 不自动重发 tools/call，断流时可能按 SDK 协议恢复 SSE 读取。

Worker 崩溃恢复仍可能重新请求模型和远端查询，结果可能变化或重复计费；不提供 exactly-once 或外部写操作恢复。MCP endpoint、服务凭据与调用者授权由当前部署配置决定；配置变更须重启相应进程，已绑定路由或批准版本改变会拒绝旧快照调用。MCP 读取不授予跨用户任务访问权限。
