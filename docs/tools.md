# 版本化工具与执行记录

当前工具执行入口由注册表、运行快照、服务端允许列表和执行记录组成。模拟 Harness 与 Chat Completions Harness 使用相同的参数验证、执行和结果验证路径。

本阶段只运行无外部副作用的内置纯函数。企业身份与角色权限、人工审批、外部业务写入、Docker 命令和文件执行仍未接入。

## 已注册工具

| 版本引用 | 输入 | 输出 | 边界 |
| --- | --- | --- | --- |
| `example_report@1` | `{"text":"需要整理的内容"}` | 包含报告草稿文本的对象 | 格式化输入，不做事实核验，不产生文件 |
| `text_stats@1` | `{"text":"需要统计的文本"}` | 字符数、非空白字符数、行数、空白分隔片段数 | 字符数按 Unicode 码点；不是中文分词或模型 token 数 |

输入最大 10000 字符，拒绝空白文本、额外字段和错误类型。工具声明输入与输出 schema，执行结果必须满足输出 schema 和大小限制。异常以稳定错误码返回，不暴露异常正文。

注册表位于 `packages/runtime/agentforge_runtime/tools.py`，新增工具需显式注册名称、版本、输入输出、实现及作用类型，并提供对应行为测试。不加载用户提交的 Python、文件路径或动态导入表达式。`read`、`write` 类型即使被注册也不能在当前执行器运行。

## 选择与权限

Agent 创建或完整更新可以提交工具子集：

```json
{
  "name": "文本分析助手",
  "instructions": "先统计文本，再按需要生成报告草稿。",
  "tools": ["text_stats@1", "example_report@1"]
}
```

更新时还需 `expected_version`。省略 tools 默认选择 `example_report@1`；显式 `[]` 表示不使用工具。同一 Agent 不能选择同一工具的两个版本。未知版本或未获允许的工具返回 422。更新创建新 Agent 版本，已存在会话和 Run 仍使用原快照。

服务端启动时读取 `AGENTFORGE_ALLOWED_TOOLS`，默认值为 `example_report@1,text_stats@1`。逗号分隔，空值禁用全部业务工具（已绑定 Skill 的内部 skill_read 仍可读取本次快照），拼写错误导致启动失败。API 与 Worker 应配置相同允许列表；修改后重启对应进程。Python 内部直接构造 Worker 时通过 `allowed_tools` 显式传入覆盖值，CLI 自动读取环境配置。

运行时再次检查固定版本、注册表和 Worker 当前允许列表。旧快照不授予绕过当前策略的权限；已撤销的工具使任务在模型请求前以 `tool_not_allowed` 失败，不静默改用其他版本。此允许列表属于部署级能力限制，尚不等于企业 RBAC；用户、空间和租户仍使用开发身份范围。

独立 Run 默认选择报告工具；该工具被服务端禁用时，独立 Run 使用空工具列表。会话 Run 始终采用已固定的 Agent 工具列表。模拟模式先读取第一个已绑定 Skill，再选择配置中的第一个业务工具，仅验证基础执行；无业务工具时返回明确标识的离线回复。真实模型由模型决定使用哪一个已授权工具。

## 执行与恢复

1. 先校验一整批模型工具调用，全部有效后才开始执行；未知工具、错误参数和重复模型调用 ID 不会触发部分执行。
2. 检查有效租约，将 `tool_started` 事件与执行记录放在同一个事务中。
3. 执行纯函数；验证输出，再在同一事务中保存结果和 `tool_completed`。工具失败则保存公开错误码和 `tool_failed`。
4. 取消、失去租约或被新尝试接管后，旧执行不能保存结果；取消、后续接管或运行结束事务会将未完成记录标为 `abandoned`；仅租约过期而尚未接管时，记录可能仍为 running。这表示结果未被接受，不宣称已强制终止同步函数。

记录绑定 Run、Attempt、模型调用 ID、工具名称及版本，保留规范化参数、参数摘要、输出、状态和时间。同一次 Attempt 内，已成功且参数一致的调用 ID 可以复用结果；参数变化或调用仍在执行时拒绝再次执行。同一批或后续模型轮次主动重复调用 ID，仍按模型协议错误处理。

崩溃恢复继续沿用原有“从头执行”机制，新 Attempt 会产生独立工具记录，可能重做纯函数和模型请求；不提供跨 Attempt 的外部副作用去重或 exactly-once 保证。审批、工具检查点和不确定结果核对将另行实现。

## 查询与调试

- `GET /api/v1/tools`：当前允许的工具及输入输出 schema，需要 Bearer 认证。
- `GET /api/v1/runs/{run_id}/tool-calls?after=0&limit=100`：查询调用记录，返回 items 和 next_cursor。
- 工具事件继续通过原有 `/events`、`/events/stream` 接口读取。

调用列表按工具开始事件序号分页，状态更新不会改变序号；收到工具完成或 Run 结束事件后，重新读取对应页面获取最终状态。事件中仅放工具标识、版本、Attempt 和错误码；完整参数及结果仅通过受范围权限约束的调用记录接口返回。

执行记录可能包含业务文本，应按任务数据保护。查询始终校验租户、空间和用户，越权与不存在均返回 404；客户端或模型不能通过参数设置身份。

手动验证可在 `/docs` 中查看工具目录，创建包含 `text_stats@1` 的 Agent 和会话，提交一段文本，运行一次 Worker，再查询调用记录、结果和事件。模拟模式不需要模型密钥。完整会话操作见 [Agent 与会话](conversations.md)。

## 数据库与错误码

迁移 `0004` 只新增 `tool_calls` 表，保留 `0003` 的 Agent、会话、Run、消息和执行尝试，不推测历史工具结果。开发库需显式执行 `uv run --env-file .env --locked alembic upgrade head`；应用启动不自动迁移。

新增错误码：`tool_execution_failed`（实现抛出异常）、`tool_invalid_result`（结果不满足契约）、`tool_call_conflict`（同一尝试中的调用标识冲突）。`tool_not_allowed` 与 `tool_invalid_arguments` 继续有效。

## Skill 读取工具

Skill 正文与实际 Tool 分开管理。Worker 在 Run 绑定 Skill 时提供内部 `skill_read@1`，只能读取本次快照中的技能，仍走统一工具记录和租约检查；这项纯读取能力不授予任何业务工具。无 Skill 的 Run 不暴露此工具。Skill 的 `required_tools` 由绑定时校验，不自动扩大部署允许列表。接口及流程见 [Skill 安装](skills.md)。
